# Qwen3.8-Flash-Next JANGHT: sub-2-bit JANGT runtime (vmlx-swift)

Branch `feat/q38-janght-lowbit`, from `vmlx-origin/main` @ `8467b0e34`. Local commits only. Nothing here is pushed,
tagged or released.

This ports vMLX Python `aeeb90b7` (JANGT K=1/K=1.5 and masked tail blocks) and `d53780ac` (qwen4_exp installs JANGT
routed experts) from `~/mlx/vmlx-q38-janght-20261016` (branch `codex/q38-janght-lowbit`) to the Swift runtime that
Osaurus uses. The goal is that Osaurus can later run the Qwen3.8-Flash-Next (qwen4_exp) JANGHT bundle.

Everything below was checked with synthetic weights. **No real bundle has been loaded or verified in this runtime.**
Before any upload, coherent generation still has to be shown on the assembled bundle in the real runtime.

## What changed

### 1. Trellis widths K = 1 and K = 1.5 (`Libraries/MLXLMCommon/JANGTKernels.swift`)

- **Code definitions.**
  - `JANGTCode.kpat(1.5) = (4, 2)` and `kpat(1) = (2, 2)`.
  - Hash multipliers: `mult[1.5] = 2124823417`, `mult[1] = 590428815`.
  - Exact float32 code statistics for both widths. These are numpy's float32 mean/std over the 4096 states,
    computed by the encoder's own `code_stats`.
  - All of these match the encoder registration (`jt_patch.py`) and vMLX Python `v2l.py`. A test pins them against
    golden values generated by the encoder.
- **One window rule for every width** (`JANGTCode.window`, `JANGTKernelSource.windowLoad` / `stepExtract`, ported
  from Python `_window` / `_window_load` / `_step_extract`). It replaces the old `k == 2` / "else 3 words" branches in
  the decode dot (`tdot`) and in the NAX prefill tile loader (`JANGTPrefillKernel.loaderSource`). A 16-weight lane
  (8 steps) uses PL bits:

  | K   | PL (bits) | Max sub-word shift | Words loaded | Realigned into |
  |-----|-----------|--------------------|--------------|----------------|
  | 1   | 16        | 16                 | 2            | `a0` only      |
  | 1.5 | 24        | 24                 | 2            | `a0` only (so[7] + L = 20 + 12 = 32) |
  | 2   | 32        | 0                  | 2            | static, unchanged |
  | 2.5 | 40        | 24                 | 3            | `a0`/`a1`, unchanged |
  | 3   | 48        | 16                 | 3            | `a0`/`a1`, unchanged |

  The generated Metal for K=2, 2.5 and 3 is unchanged.
- **Dequant path and WPL fast path.** The Swift runtime has no dequant path (Python `dequant_rot`) and no word-aligned
  WPL fast path; it only ports the v3 decode kernels. Neither applies here. The Qwen dims would not use the WPL path
  in any case: it needs kin % 1024/2048 == 0.

### 2. Masked tail block for kin % 512 != 0, every width (`JANGTKernels.swift`)

The gate/up and down decode kernels looped `for (k0 = 0; k0 < kin; k0 += 512)`. At the Qwen down width kin = 640,
the second pass read 512 inputs past the row: the next token's activations, and words past the row's packed data.
This was wrong for every width, not only for the new ones.

`JANGTKernelSource.blocks` (the Python `_blocks` port) now runs the full blocks unmasked, followed by one tail block in
which only lanes `j < (kin % 512) / 16` decode. Tail lane j sits at the same bit offset `j * PL` of its block as in a
full block. The `simd_sum` epilogue stays outside the divergent branch.

The prefill tiles were already correct at kin = 640: they step through 64-column tiles, and 640 % 64 == 0.

### 3. qwen4_exp installs JANGT routed experts

The Swift JANGHT path already had per-module mixed layers (`JANGTRoutedExpertLayer`, built by
`JANGHModelPreparation.makeRoutedExperts` whenever a (layer, role) is `mode: jangt`). The qwen4_exp bundle still could
not reach that path, for five reasons:

- **Detection** (`JANGHModelPreparation.declaresCustomFormat`). Only `mode: jangtq2` counted as a custom format, so a
  pure-JANGT bundle fell through to the strict ordinary decoder, which refuses `mode: jangt`. Now `mode: jangt` counts
  as custom too.
- **No codebook header** (`JANGHFormatContract`, `JANGHConfigurationPartition`). Both required a `jangtq` header. The
  Qwen3.8 JANGHT assembler writes none, because every routed projection is JANGT. The header is now optional when
  there is no `jangtq2` projection and a `jangt` block exists. A `jangtq2` projection without a header is still
  refused.
- **Declared code tables** (`JANGTCode.validateDeclaredCode`). If a bundle declares `jangt.code_multipliers` /
  `jangt.step_bits`, they must match the runtime code; a mismatch is refused. Decoding with another code is garbage,
  not a degraded model. Bundles without the tables (GLM-5.3, N0.5) are unaffected.
- **Geometry.** `JANGTProjection` and `JANGHTensorIndexPlan` required kin % 512 == 0, which refused kin = 640. They now
  require kin % 128 == 0, the Hadamard-128 basis. The tail is handled by the kernels.

  `outliers <= 32` is now also asserted in `JANGTProjection`. `JANGHTensorIndexPlan` already asserted it. The reason:
  the decode kernels give each outlier column one SIMD lane, so more than 32 columns would be dropped silently. The
  encoder default is 8. This is a format-integrity check, as the brief asked ("keep or assert, don't silently widen").
- **Exclusion check** (`Qwen4Exp.init(_:requesting:routedExperts:customRoutedTensorNames:)`). It accepted only the
  `tq2_packed`/`tq2_scales` names. It now uses `JANGHModelPreparation.isCanonicalRoutedExclusionSet`: every routed
  (layer, role) must be exactly one whole format, either the codebook pair or the JANGT set, and nothing else.

How kbits and ownership work:

- **Per-unit kbits** come from `quantization["model.layers.L.mlp.switch_mlp.<proj>"] = {"mode": "jangt", "kbits": K}`
  through `contract.trellis`. Gate and up must share one width. Down may differ.
- **JANGT owns the routed stacks** even when a `jangtq` block is present. Each module is resolved by its own mode. A
  `jangtq` header only supplies codebooks to `jangtq2` modules, so it never turns JANGT modules into JANGH ones.
- **Left unchanged:** MTP experts (affine), shared experts, routers and the PLE path.

### 4. Text-only qwen4_exp bundles through the factory Osaurus uses

`qwen4_exp` is registered only in `VLMModelFactory`. Osaurus calls `loadModelContainer(from:using:configuration:
loadConfiguration:)`, which tries the VLM factory first and then the LLM factory.

- **The model itself was already text-only capable.**
  - `Qwen35Configuration.visionConfiguration` is optional.
  - Without it, `constructibleModalities` is `[.text]`, so no vision tower is built.
  - `sanitize` drops `visual.*`.
  - `prepare` refuses media when there is no tower.
- **The blocker was the processor.** The VLM factory always builds the input processor from
  `preprocessor_config.json` / `processor_config.json`. The JANGHT assembler ships neither, so the load threw
  `configurationFileError("preprocessor_config.json")`, and only after the weights had been read.
- **Fix** (`Libraries/MLXVLM/Qwen4ExpTextOnlyBundle.swift`, wired into `loadProcessorConfig`). For a qwen4_exp
  `config.json` with no `vision_config` and no processor files at all, a `Qwen3VLProcessor` configuration is
  synthesized. It uses the Qwen3.8 vendor geometry: patch 16, merge 2, temporal 2, mean/std 0.5. Those image values
  can never reach a model, because the model has no tower and refuses media.
- **Scope.** Any processor file on disk, a `vision_config`, or another model type turns the fallback off. A test
  checks this.

## Tail-bug control (fails before, passes after)

The test is `JANGTLowBitKernelTests.testDownEveryWeight*Kin640` / `testGateUpEveryWeight*Kin640`. It feeds one-hot
inputs to the rotated and the raw input, so output row t is column t of one expert's effective weight matrix. That
makes every weight checkable at fp32-exact tolerance, including columns 512..639 and the outlier columns.

**Control setup.** The library changes were stashed, which gives the `8467b0e34` kernels. Only the `inputs % 512` guard
in `JANGTProjection` was relaxed, so that a kin = 640 projection could be constructed at all. Then K=2 and K=2.5 were
run; K=1 and K=1.5 do not exist in that code.

| Test (baseline kernels, kin = 640) | Weights wrong |
|---|---|
| down K=2, N=2560    | 980,480 / 1,638,400 (59.8 %) |
| down K=2.5, N=2560  | 980,480 / 1,638,400 (59.8 %) |
| gate/up K=2, N=256  | 98,048 / 163,840 (59.8 %) |
| gate/up K=2.5, N=256| 98,047 / 163,840 (59.8 %) |

**Same tests after the fix:** 0 wrong for K in {1, 1.5, 2, 2.5}.

**What the 59.8 % is.** It is the read-past bug: 383 of the 640 one-hot rows pick up a second block read from the next
token's row. The Python control measured 59.7 % at K=2. The broken outputs sit in columns 0..382, not in the tail
columns. So any width at I = 640 was wrong before the fix, not only the tail.

**Factory control.** `testTextOnlyBundleLoadsThroughTheRoutedFactory` was run with the processor fallback disabled.
It fails with `configurationFileError("preprocessor_config.json", ...)`, and passes with the fallback.

### `Tests/MLXLMTests/JANGTEncoderGolden.swift`

Golden values generated by the encoder: jang-tools `jang_tools/jangt/v2l.py` with `jt_patch.py`,
`JANGT_HB=128 JANGT_L=12`, on the CPU. For K in {1, 1.5, 2, 2.5, 3} it holds:

- the multiplier, kpat, and words per row at 640 / 2560;
- an FNV-1a hash of every state's value pair;
- two random 640-wide rows: their packed words, the hash of the decoded values, and 18 probe values.

The generator script is `golden.py` in the session scratchpad; it is not committed. It runs `VL.unpack_states` +
`VL.values_of` on numpy-random words.

### `Tests/MLXLMTests/JANGTLowBitKernelTests.swift`: 25 tests, 25 passed, 175.8 s

- **Code vs the encoder golden.** Bit-exact for all five widths: multipliers, kpat, words per row, all 4096 state
  values, and the decoded 640-wide rows.
- **Lane geometry.** The window table above, and that the last tail lane stays inside words_per_row at kin = 640.
- **Declared-table validation.** Good tables, absent tables, a wrong multiplier, a wrong step pattern, an unknown
  width.
- **Decode, every weight** (one-hot inputs):
  - down: kin = 640 for K in {1, 1.5, 2, 2.5}, and kin = 2560 for K in {1, 1.5};
  - gate/up + SwiGLU: kin = 2560 and kin = 640 for all four widths;
  - 0 wrong everywhere: fp32 tolerance 1e-6 for down, 2e-5 for SwiGLU (fast exp);
  - includes the outlier columns, -1 padding, and expert index 1.
- **Decode, composed routed path vs a float64 dense reference** at D=2560, I=640, E=6, 2 tokens x 4 slots. The path
  has layer-wide gate/up outliers, per-expert -1-padded down outliers, and column scales. Measured rel-L2:

  | K (gate+up / down) | gate/up | down (kin 640) |
  |---|---|---|
  | 1 / 1     | 6.77e-4 | 4.40e-4 |
  | 1.5 / 1.5 | 6.94e-4 | 4.85e-4 |
  | 2 / 2     | 7.04e-4 | 4.95e-4 |
  | 2.5 / 2.5 | 7.05e-4 | 4.65e-4 |
  | 1.5 / 2   | 7.02e-4 | 4.80e-4 |
  | 1 / 2.5   | 7.34e-4 | 4.84e-4 |

  These are the same order as the Python measurement (7.0e-4 / 4.8e-4). The test asserts rel-L2 < 5e-3 and < 3x the
  K=2 error.
- **Negative control.** The same rows decoded with the K=2 code at the K=1.5 bit positions give rel-L2 > 0.3 against
  the kernel. The kernel matches the right code at < 1e-6.
- **NAX prefill tiles, every weight.** One-hot bf16 rows, two experts, gate (kin 2560) and down (kin 640), all four
  widths: 0 of 3,276,800 outputs differ from bf16(value x scale). They are bit-exact.
- **NAX prefill composed**: fused gate/up with the outlier epilogue, plus a down with the outlier term, 72 sorted rows
  over a ragged expert split. Fused rel-L2 is 2.92e-3 to 2.96e-3; down (kin 640) is 2.33e-3 to 2.35e-3. That is bf16
  tiles against a bound of 2e-2.
- **Projection admission.** 640 and 2560 are admitted for all four widths. Refused: a wrong word count, kin = 600,
  33 outlier columns, and K = 0.5.

### `Tests/MLXLMTests/Qwen4ExpJANGTPreparationTests.swift`: 6 tests, 6 passed

The fixture is a tiny qwen4_exp: hidden 256, moe_intermediate 128 (so down kin = 128 is a tail-only block), 16
experts, top-10, 2 layers. Widths are mixed as in Python: layer 0 gate+up 1.5 / down 2, layer 1 gate+up 1 / down 2.5.
There is no `jangtq` header and no `vision_config`. Bank shards use the aligned layout.

- **Admission and construction.** `declaresCustomFormat`, the 36 exclusions, canonical exclusion set, no `jangtq`
  invented, ordinary entries `false`. The constructed model has modalities `[.text]`, both routed layers are
  `JANGTRoutedExpertLayer`, and there is no JANGH layer.
- **Routed layers vs float64 reference.** rel-L2 per route:

  | Layer | Decode, T=3, fp32 | Decode, T=3, bf16 | NAX prefill, T=60 (600 slots), bf16 |
  |---|---|---|---|
  | 0 | 8.1e-4 | 1.8e-3 | 4.8e-3 |
  | 1 | 8.0e-4 | 1.9e-3 | 4.8e-3 |

  These match Python's 8.6e-4 decode and 4.8e-3 / 4.9e-3 prefill.
- **JANGT owns the routed stacks** when a `jangtq` codebook header is also present.
- **Failing closed.** Refused: a wrong declared multiplier; a `jangtq2` projection without a header; K declared 1.5
  with K=2 rows stored; gate and up at different widths; a missing routed projection.
- **Processor fallback scope.** It synthesizes for text-only qwen4_exp only. It does not synthesize with a
  `vision_config`, for another model type, or when `preprocessor_config.json` exists.
- **`testTextOnlyBundleLoadsThroughTheRoutedFactory`.** A complete synthetic bundle: ordinary bf16 weights from the
  model's own parameter tree, two JANGT bank shards, and no `vision_config`, `visual.*` or processor files. It is
  loaded with `loadModel(from:using:)`, the same routed VLM-then-LLM loader as Osaurus' `loadModelContainer`. Checks:
  - the result is `Qwen4Exp` with modalities `[.text]` and two `JANGTRoutedExpertLayer`;
  - the synthesized processor tokenizes a chat;
  - a 64-token forward (640 routed slots: the prefill route) and then a 1-token decode step give finite, live logits.

## Not done / open

1. **No real-bundle run.** The bundle is not assembled yet, and this Mac was busy with the quantization job. Text-only
   loading through the Osaurus path is confirmed by a test on a synthetic bundle (factory test above), not on the
   real bundle. The real bundle also carries an MTP head with 2-bit/g64 affine experts, a PLE n-gram table (affine
   8-bit/g32, SSD-backed) and a `mtp_draft/` sidecar; the synthetic one has `ple_layer_ids: []` and no MTP. Those
   paths are the existing Allosaurus ones, unchanged here.
2. **Decode/prefill crossover for Qwen is not measured.** `JANGTRoutedExpertLayer.sortThreshold` is 512 routed slots,
   measured on GLM-5.3 and N0.5. At top-10 that is 52 tokens. Python uses 72 slots; the Qwen JANGH path was tuned to
   96 tokens.
3. **Speed not measured** for K=1/1.5 decode. As in Python, a 2-word realigned window is the K=2.5/3 work minus a word.
4. **Outlier columns need `jt_cs = 1`.** The runtime applies down outlier weights without the column scale; the
   encoder keeps cs = 1 there. Same invariant as Python.
5. **Gate/up outlier columns are layer-wide** (taken from expert 0 for the input mask). This is the existing
   contract, the same as Python.
6. **Osaurus-side metadata.** Osaurus may label or gate bundles by `jang_config.format` (`jangtq2` for this bundle)
   or by capabilities. That is not checked here.
