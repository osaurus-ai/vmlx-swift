# Native SeedVR2 3B upscaling

Implemented in #597, following the image workflow contract change (#596). This replaces the previous
`notImplemented` upscaler with the SeedVR2 3B one-step restoration pipeline.

The local export contains `config.json` (`model_type: seedvr2`,
`variant: seedvr2-3b`), `transformer.safetensors`, `vae.safetensors`, and
`pos_emb.safetensors` with a `[58,5120]` positive embedding. Float and affine
8-bit/group64 transformer exports are supported. The VAE stays floating point.
Weights and shapes are strictly validated; missing embeddings never trigger a
network download. There is no prompt tokenizer or text encoder for this model.
The 7B architecture is not implemented and is rejected explicitly.

Requests accept 2x or 4x, PNG, and an optional UInt64 seed. Output keeps the
source aspect ratio and is limited to 4096² pixels in this implementation.
SeedVR2 always executes its distilled single step at guidance 1, including old
callers that send a different step count. Completion reports actual dimensions,
scale, seed, step count and scheduler. RNG uses the reference's original
`normal(key(seed))` path; it is not split or reseeded per tile.

`FluxEngine.upscale(request, interrupt:)` and `UpscaleRequest.interrupt` expose
cooperative cancellation. The producer checks between transformer blocks, VAE
stages/tiles and CPU preprocessing/color-transfer rows. The consumer must drain
before releasing its GPU lease. A cancelled job emits `.cancelled`, writes no
output, and releases its temporary tensors. Loaded model weights remain resident.
Concurrent calls to one SeedVR2 instance queue on its producer queue.

Preprocessing follows Pillow bicubic coefficients and reads RGB values without
an unintended macOS color-space conversion. VAE tiles follow mflux's 512px/64px
cosine-overlap assembly. Color transfer uses CPU float32 and stable rank ordering:
the initial GPU port changed tied LAB ranks and produced isolated incorrect pixels.

## Verification

`swift test --build-system swiftbuild --filter SeedVR2Tests` runs metadata,
validation, Pillow-resize and stable-rank tests without downloading weights.
Optional real-weight tests use `SEEDVR2_TEST_BUNDLE`, `SEEDVR2_TEST_FIXTURE`,
`SEEDVR2_TEST_SOURCE`, `SEEDVR2_TEST_FULL_FIXTURE`, and `SEEDVR2_TEST_OUTPUT`.
Fixtures are independently generated by mflux; no weights are committed.

Initial component comparison: seeded noise max error 2.98e-8 across MLX builds;
VAE/DiT max differences below 0.008; color transfer on identical input below 1e-6.
Raw source preprocessing matches the reference exactly. Full-image comparison
against mflux measured mean absolute error 0.045/255, max 2/255 and PSNR 61.56 dB.
This is numerical parity evidence, not a perceptual-quality benchmark.

The isolated Osaurus Release app at engine `3672641a9` completed 512→1024 in
9.7 s and a post-cancellation 1024→2048 job in 24.5 s (seed 7). A 1024→4096
job cancelled after its denoise step returned to cancelled UI in 0.376 s and
wrote no file. Peak physical footprint was 42.58 GB for the first job and
50.90 GB for the larger cancelled job, settling to 5.07/5.40 GB respectively.
Loaded weights remain resident; these measurements do not claim model-size-only
RAM or faster performance than another implementation. CPU builds ran concurrently.

Source and live receipts: [engine #597](https://github.com/osaurus-ai/vmlx-swift/pull/597#issuecomment-6182820680)
and [Osaurus #3096](https://github.com/osaurus-ai/osaurus/pull/3096#issuecomment-6182698958).
The app's shared image-tool path also generated/edited Turbo images with correct
metadata and model handoff; the surrounding text-agent task hit its output limit
and is not counted as an end-to-end agent success. SeedVR2 itself is upscale-only.
The UI still labels preprocessing/encode work as Loading until the first denoise
event; richer stage progress remains a follow-up.
