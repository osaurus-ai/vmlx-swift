# Bonsai2 attention KV precision

Status: component verification in progress; pinned-app proof pending. No speed claim.
Base:125f961272908697f87a983f972ccf50e0810a05 (merged packed-load/media-prefill).

## Mechanism and scope

Bonsai2 preserves its exact F16 affine metadata and F32 norms, signs and state
projections. MLX rms_norm uses result_type(input,weight), so F32 norm weights
promote the activation path. Attention currently caches projected K/V without
an explicit storage dtype. The retained native app logs show F32 GDN activations;
the configured FP16 cache label alone does not establish attention tensor dtype.

Implement FP16 Q/K/V only at the attention boundary after normalization/RoPE,
selected by actual Hadamard projection modules, for both text and VLM routes.
Preserve the projection/gating output dtype and all stored weights. GDN/SSM
recurrence remains F32: rounding recurrent state at cache boundaries changes the
recurrence and is not equivalent to reducing attention KV storage.

The same policy must apply on cold, prefix-restored, rotating and batched paths.
Keep cache offset/ring metadata intact when converting a pre-existing floating
attention cache. Quantized/TurboQuant storage must not be reinterpreted as plain
K/V. ModelContainer cache keys must distinguish the new numerical policy from
old F32 checkpoints. Media, reasoning and tool/schema salts remain unchanged.

## Restore regression caught before app merge

The first executable component run at 1623bb45 built successfully, then reported
32 issues across 47 tests: 26 exposed the existing standard disk restore's
unconditional FP16-to-BF16 conversion; 6 were new tests reading the compiled
ring's intentionally stale Swift offset instead of its live tensor counter.
Cold/decode precision, batched attention, both tiny VLM towers, actual-bundle
protocol/media processing and the remaining suites passed. These are component
results, not full-model native-app proof.

The correction makes dtype preservation model-owned and opt-in. Both container
caching entrypoints select it from installed Hadamard modules. A typed disk
marker preserves native standard K/V on reopen; paged restore carries the same
coordinator policy through AR, batch and speculative restore call sites. Other
models, unmarked old records, QSA and legacy disk formats keep their previous
behavior. GDN/SSM state serialization and recurrence are unchanged. Malformed
precision metadata is a clean cache miss. Strict tensor/logit equality for a
canonical tool-boundary disk reopen is retained, not relaxed.

Actual old native run8 files at 10,099 tokens contained 32 F32 attention tensors
(1,323,696,128 bytes) and 48 F32 recurrent tensors (150,994,944 bytes), despite the
UI's nominal FP16 label. Their headers, exact logged hashes and file sizes are
retained in `fp16-baseline-run8-cache-dtypes.json` under the evidence directory.
