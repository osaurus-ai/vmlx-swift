# Cold-tier removal

#632 removes the JangPress/MLXPress cold-weight subsystem. It removes router observation, cold-page sweeps, prompt-token host readbacks used only by the embed tier, loader activation and status/policy APIs, separate mmap/embed caches, Mach purgeable weight copies, experimental prestack/overlay creation, and the standalone MLXPress products. The Osaurus companion removes the corresponding setting and status response fields. Persisted old settings are ignored, not reactivated.

Canonical model loading remains: original bundle identity, safetensors mmap, explicitly authorized alignment repair, model residency leases, affine/JANGH/JANGTQ matmul, Hadamard/trellis transforms and active routed-tensor reads. `MappedSafetensorsShard` extracts the read-only shard/index/range reader used by affine streaming; it has no eviction/advice API. `LegacyRoutedTensorLayout` only recognizes already-existing stacked weight layouts; it cannot create an overlay. Historic MLXPress-prefixed profiling and kernel-selection names are not the retired cold-tier subsystem and retain their existing behavior.

The runtime's typed `loadModel(...loadConfiguration:)` now returns `ModelContext` directly. Cold-tier tuple handles and legacy activation overloads are removed. Repository benchmark clients migrate to that API. This is a source-breaking removal for external callers of the retired API/products; ordinary model-container loading remains available.

## Validation and boundaries

- The complete removal builds through the runtime and benchmark clients. 102 focused loader, settings and storage tests pass (49 loader/storage plus 53 settings/capability tests).
- Focused coverage includes legacy-setting migration, load configuration, canonical shard reads and explicitly authorized storage repair. Tests of deleted cold-tier behavior are retired with those APIs; quantized compute/cache tests are retained. The mixed source-contract suite retains an unrelated stale AttentionUtils string expectation on unchanged code; full-suite green is not claimed.
- Isolated Release Osaurus app 961453d4720c40d2c99e6af687e445cd9f4e4302, pinned to production removal 0e73bbcfc7f01def6cab2b522acabbfed8131dff, completed connected calculator chats on Ornith 122B JANGH2 and MiniCPM V4.7 35B JANG_4M. Visible answers were correct and subsequent tool steps restored SSD state. PR #632 and app #3156 carry the source/binary identities and raw evidence paths.
- Activity Monitor qualification: process footprint was only about 2–3 GB during intervals when host wired memory rose by tens of GB. H2 wired memory returned near baseline on idle unload. These receipts do not establish low total model RAM, all-family safety or absence of duplicate long-context caches. App #3157 and engine #633 track reporting fixes; the larger memory-lifecycle investigation remains open.
- No speed or RAM reduction is claimed from deletion alone. Most production paths already disabled cold-tier activation. The explicit disk-quota defect (#630) and consumerless KV checkpoint defect (#631) are independent, evidenced fixes.
- This does not claim all model families hold no transient RAM. Active KV, recurrent state, speculative verification and bounded asynchronous write ownership still need RAM. Remaining cache-enabled long-context retention and process-wide write budget accounting are tracked separately.
