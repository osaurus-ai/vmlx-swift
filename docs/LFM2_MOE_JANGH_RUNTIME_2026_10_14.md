# LFM2-MoE JANGH routed runtime

Directory-backed admission uses `model_type: lfm2_moe` and the actual per-module `jangtq2` declarations in config.json. It does not identify quantization from the folder name. Architecture dimensions and shard headers must match every routed projection in the sparse layers. Affine LFM follows its existing loading path.

LFM expert paths are `model.layers.L.feed_forward.switch_mlp.{gate,up,down}_proj`, distinct from the `mlp.switch_mlp` namespace used by other routed families. The common layout has an explicit feed-forward child; its default remains `mlp`. Only the LFM architecture admits `feed_forward`. The mmap fork must include the canonical LFM namespace change in osaurus-ai/mlx#23.

The shipped 24B bundle has 64 experts, top-4 routing, 38 sparse layers following two dense layers. Gate/up codebook banks are U32 `[64,1536,128]` plus F16 scales `[64,1536]` (2 bits). Down banks are U32 `[64,2048,144]` plus F16 scales `[64,2048]` (3 bits). Config codebooks and normalized Hadamard-32 rotation remain authoritative. No JANGT trellis path or random signs are substituted. Banks stay packed and mapped in opaque owners; their exact keys are excluded from generic weight loading. No dense expert placeholders are retained beside them.

The existing fused gate/up and weighted-down decode kernels and sorted packed-tile prefill kernels are reused without arithmetic changes. The router retains unbiased activation-dtype sigmoid weights, float32 checkpoint expert bias for selection only, and the original normalization/scaling. Dense/attention/conv projections and tied embeddings remain ordinary affine; no independent lm_head is created. Current shared JANGH decode reduction uses its existing float32 fused reduction, while prefill contributions round in projection dtype. Cross-runtime correctness and chunk-size sensitivity still require model-level proof; lower loss alone is insufficient.

The LFM sidecar uses `format: jang`, `format_version: 2.0`. Its quantization section is descriptive, not executable. The loader preserves config.json as the sole plan/header owner, checks known summary widths against the plan, permits harmless descriptive notes and unordered modes, and rejects per-module ownership, per_tensor plans or conflicting headers. Existing other-family sidecar rules are unchanged.

Native BF16 attention KV storage is 20,480 bytes per token (10 layers × 8 KV heads × 64 dimensions × K/V × 2 bytes), approximately 2.5 GiB at 131,072 tokens. Conv state is additional. SSD prefix storage does not eliminate active KV needed by attention, so measure physical footprint rather than infer it from bundle size or disk caching.

Focused checks cover actual mounted-bundle headers, synthetic namespace/summary/mode rejection, mapped installation, exact exclusions and absence of duplicate dense expert arrays. Real Osaurus generation, multi-turn cache restore, tool calls, terminal wait, sustained decode/prefill, RAM and 128k behavior remain the integration acceptance gate. No sampler, generation config, cache dtype, or quantized-KV behavior is changed here.
