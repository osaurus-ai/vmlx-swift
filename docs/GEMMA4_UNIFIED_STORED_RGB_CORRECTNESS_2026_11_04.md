# Gemma unified stored RGB preprocessing — 2026-11-04

Status: separate source candidate after merged norm PR723. Numeric production-processor tests pass; native candidate qualification, CI and consumer landing remain pending. No release tags or publishing.

The unified image processor reference rescales stored RGB samples by 1/255 without ICC gamut conversion. The current Gemma processor renders through CoreImage's managed working gamut with a tone-curve filter. That preserves the test's sRGB pixels but changes Display P3 and Rec.2020 pixels. A new test exercises the actual `Gemma4Processor.prepare` method with real encoded PNGs and a deterministic image-placeholder tokenizer. Dimensions exactly fill 70 pooled patches, avoiding interpolation differences so the test isolates color processing. Independent CPU raw-byte values provide the expected pixels.

Baseline runtime `4a76ab058da9c515b4c71e5b236f1977a7217869` passes the sRGB case but fails Display P3 (maximum error 0.6705315) and Rec.2020 (1.0248828). The framework reports four issues for those two failing parameter cases. The correction composites transparency onto white before the existing resize and uses the existing unmanaged rendering helper, only for `Gemma4UnifiedProcessor`. Ordinary Gemma processor behavior is unchanged. No model weights are loaded by this test.

The corrected selection passes 27 SwiftTesting tests in four suites, including all three production-processor color cases, unmanaged media parity, media determinism, VLM cache scope and Gemma VLM tests; 2 XCTest tests also pass. A follow-up passes 14 XCTest tests and one SwiftTesting test with three color cases, checking repeated production media salts and the existing media-cache/dtype contracts. The pinned backend conversion chain also explicitly composites alpha onto white. An additional production test reproduced three half-transparent failures (error 0.49996158) after the first RGB-only correction. White compositing fixes that contract. The expanded selection passes 14 XCTest tests and 27 SwiftTesting tests in four suites, including nine actual processor cases across three color spaces and opaque/half-transparent/fully-transparent input. Repeated prepared media salts match in each case. Original red and initial green attempts remain separate artifacts.

Pixel bytes already participate in `computeMediaSalt`, so changed prepared pixels isolate cache state; no cache deletion is needed. Resizing parity beyond the no-resize fixture and causal improvement in model OCR are not established by the numeric test.
